O sistema é distribuído como um conjunto de imagens Docker publicadas no **GitHub Container Registry (GHCR)**. O deploy em produção é totalmente automatizado via **GitHub Actions** e um script shell.

## Visão geral da infraestrutura

```
GitHub (push para main)
        │
        └─► GitHub Actions (CI/CD)
                │
                └─► Build das imagens Docker
                        │
                        └─► Push para GHCR
                                │
                                └─► Servidor de produção
                                        │
                                        └─► deploy.sh
                                                │
                                                └─► docker compose up -d
                                                        ├─► app    (Nginx :80)
                                                        ├─► server (Fastify :3333)
                                                        ├─► iot    (Aedes :1883/:9001)
                                                        └─► postgres (:5432)
```

## Arquivos Docker

| Arquivo | Uso |
|---|---|
| `docker-compose.yml` | Base compartilhada entre ambientes |
| `docker-compose.local.yml` | Override para desenvolvimento local |
| `docker-compose.prod.yml` | Override para produção |
| `app/Dockerfile` | Build do frontend (React → Nginx) |
| `server/Dockerfile` | Build do backend Fastify |
| `iot/Dockerfile.mqtt` | Build do broker MQTT Aedes |
| `deploy.sh` | Script de deploy automatizado no servidor |

## Desenvolvimento local

Para rodar todos os serviços localmente com Docker:

```bash
# Sobe apenas o banco de dados
docker compose -f docker-compose.local.yml up -d postgres

# Ou sobe tudo via Docker (banco + broker + backend + frontend)
docker compose -f docker-compose.yml -f docker-compose.local.yml up -d
```

Para desenvolvimento com hot-reload, prefira rodar cada serviço diretamente com `npm run dev` (ver [Início Rápido](/docs/guia/inicio-rapido)).

## CI/CD com GitHub Actions

O pipeline é acionado automaticamente em qualquer push para a branch `main`. Ele executa as seguintes etapas:

1. **Checkout** do repositório
2. **Login** no GHCR com `GITHUB_TOKEN`
3. **Build** das imagens `app`, `server` e `iot`
4. **Push** das imagens para `ghcr.io/seu-usuario/tcc-*`

### Arquivo do workflow

O workflow fica em `.github/workflows/` e segue o padrão:

```yaml
name: Build & Push

on:
  push:
    branches: [main]

jobs:
  build:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write

    steps:
      - uses: actions/checkout@v4

      - name: Login no GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build e push — backend
        uses: docker/build-push-action@v5
        with:
          context: ./server
          push: true
          tags: ghcr.io/${{ github.repository_owner }}/tcc-server:latest

      - name: Build e push — broker MQTT
        uses: docker/build-push-action@v5
        with:
          context: ./iot
          file: ./iot/Dockerfile.mqtt
          push: true
          tags: ghcr.io/${{ github.repository_owner }}/tcc-iot:latest

      - name: Build e push — frontend
        uses: docker/build-push-action@v5
        with:
          context: ./app
          push: true
          tags: ghcr.io/${{ github.repository_owner }}/tcc-app:latest
```

## Deploy em produção

### Pré-requisitos no servidor

- Docker Engine 24+ e Docker Compose v2
- Acesso SSH configurado
- Variáveis de ambiente definidas (ver seção abaixo)

### Script `deploy.sh`

O script automatiza o pull das novas imagens e o restart dos serviços:

```bash
#!/bin/bash
set -e

echo "🔄 Pulling imagens mais recentes..."
docker compose -f docker-compose.yml -f docker-compose.prod.yml pull

echo "🚀 Reiniciando serviços..."
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --remove-orphans

echo "✅ Deploy concluído."
```

Execute no servidor com:

```bash
chmod +x deploy.sh
./deploy.sh
```

### Primeiro deploy

No primeiro deploy, além de executar o script, é necessário:

1. Criar o arquivo `.env` de produção (ver variáveis abaixo)
2. Rodar as migrations do banco:

```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml \
  exec server npm run db:migrate
```

## Variáveis de ambiente

### Backend (`server/.env`)

| Variável | Exemplo | Descrição |
|---|---|---|
| `DATABASE_URL` | `postgresql://user:pass@postgres:5432/access_control` | URL de conexão com o PostgreSQL |
| `BACKEND_URL` | `http://server:3333` | URL interna do backend (usada pelo broker) |
| `PORT` | `3333` | Porta em que o Fastify escuta |
| `BETTER_AUTH_SECRET` | `string-aleatoria-longa` | Segredo para assinar sessões |
| `BETTER_AUTH_URL` | `https://seu-dominio.com` | URL pública da aplicação |
| `SMTP_HOST` | `smtp.gmail.com` | Servidor SMTP para e-mails de reset |
| `SMTP_PORT` | `587` | Porta SMTP |
| `SMTP_USER` | `noreply@ifsp.edu.br` | Usuário SMTP |
| `SMTP_PASS` | `senha-do-app` | Senha / app password SMTP |

### Broker MQTT (`iot/.env`)

| Variável | Exemplo | Descrição |
|---|---|---|
| `BACKEND_URL` | `http://server:3333` | URL do backend para chamadas HTTP |
| `MQTT_PORT` | `1883` | Porta TCP do broker |
| `MQTT_WS_PORT` | `9001` | Porta WebSocket do broker |

> ⚠️ **Nunca commite arquivos `.env` com valores reais.** O repositório contém apenas `.env.example` com placeholders. Copie e preencha no servidor.

## Serviços no Docker Compose

### `postgres`

Banco de dados PostgreSQL. Em produção, use um volume nomeado para persistência:

```yaml
volumes:
  - postgres_data:/var/lib/postgresql/data
```

### `server` (Fastify :3333)

Backend da aplicação. Depende do `postgres` estar saudável antes de iniciar.

### `iot` (Aedes :1883 / :9001)

Broker MQTT. Expõe a porta 1883 (TCP) para os controladores físicos e 9001 (WebSocket) para clientes de browser.

### `app` (Nginx :80)

Frontend servido via Nginx. Em produção, coloque um reverse proxy (Caddy, Nginx externo ou Traefik) na frente para TLS/HTTPS.

## Checklist de deploy

- [ ] Imagens publicadas no GHCR (CI passou)
- [ ] Arquivo `.env` de produção criado no servidor
- [ ] Volume do PostgreSQL configurado
- [ ] Portas 80, 1883 e 9001 abertas no firewall
- [ ] `./deploy.sh` executado com sucesso
- [ ] Migrations aplicadas (`db:migrate`)
- [ ] Seed inicial executado (`db:seed`) — apenas no primeiro deploy
- [ ] HTTPS configurado no reverse proxy
- [ ] Teste de login no portal

## Monitoramento

Atualmente sem stack de observabilidade configurada. Para monitorar os logs em tempo real:

```bash
# Todos os serviços
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs -f

# Apenas o backend
docker compose logs -f server

# Apenas o broker MQTT
docker compose logs -f iot
```
