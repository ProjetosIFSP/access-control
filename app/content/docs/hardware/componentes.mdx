Cada controlador de acesso instalado em uma porta é composto por um conjunto de componentes eletrônicos coordenados pelo **ESP32**. Esta página lista todos os componentes e sua função no sistema.

---

## Lista de componentes

| Componente | Modelo | Função |
|---|---|---|
| Microcontrolador | Placa de Desenvolvimento ESP32 | Processamento central, Wi-Fi, MQTT |
| Sensor biométrico | HiLink ZW-101 (protocolo R30x) | Captura e matching de digitais |
| Leitor NFC/RFID | RC522 | Leitura de tags e cartões RFID |
| Módulo relê | 5V 1 canal com optoacoplador | Acionamento da fechadura via GPIO |
| Fechadura | Solenoide 12V (fail-secure) | Atuador eletromecânico da porta |
| Fonte de alimentação | 12V / 2A (Colmeia) | Alimentar a fechadura + step-down |
| Conversor step-down | LM2596 ou módulo buck | Reduz 12V → 5V para a placa |

## Microcontrolador — ESP32

O ESP32 é o cérebro do controlador. Ele gerencia a conectividade Wi-Fi, a comunicação MQTT com o broker e a coordenação de todos os periféricos utilizando interrupções e múltiplas interfaces de comunicação (UART, SPI).

### Especificações relevantes

| Atributo | Valor |
|---|---|
| Frequência | Até 240 MHz (Dual Core) |
| RAM | 520 KB |
| Flash | 4 MB |
| Wi-Fi | 802.11 b/g/n 2,4 GHz |
| Tensão de operação | 3,3 V (pinos GPIO) |
| Alimentação via USB/VIN | 5 V |

## Sensor biométrico — HiLink ZW-101

O HiLink ZW-101 é um módulo de sensor biométrico óptico que utiliza o protocolo **R30x** (compatível com a maioria das bibliotecas Arduino de fingerprint). Ele realiza o **matching on-device** — os templates são armazenados diretamente na memória flash interna do sensor.

### Especificações

| Atributo | Valor |
|---|---|
| Protocolo | R30x (UART serial) |
| Interface | UART (SoftwareSerial, 57600 baud) |
| Tensão de alimentação | 3,3 V – 5 V (tolerante) |
| Slots de template | 127 (slots 1–127) |
| Tempo de matching | 200–800 ms |
| Template size | 256 bytes (512 chars hex) |
| Falsa aceitação (FAR) | < 0,001% |
| Falsa rejeição (FRR) | < 0,1% |

### Comandos utilizados (protocolo R30x)

| Comando | Código | Descrição |
|---|---|---|
| `GenImg` | `0x01` | Captura imagem do dedo |
| `Img2Tz` | `0x02` | Converte imagem em vetor de características |
| `CreateModel` | `0x05` | Combina 2 capturas em um modelo |
| `StoreModel` | `0x06` | Salva modelo em um slot da flash interna |
| `DeleteModel` | `0x0C` | Remove modelo de um slot |
| `Search` | `0x04` | Busca matching em todos os slots |
| `GetModel` | `0x07` | Lê o template de um slot (para upload) |
| `UploadTemplate` | `0x08` | Transfere template via UART para o MCU |

### Fluxo de enrollment no sensor

```
1. GenImg()           → captura imagem (passagem 1)
2. Img2Tz(buffer=1)   → extrai vetor de características
3. GenImg()           → captura imagem (passagem 2)
4. Img2Tz(buffer=2)   → extrai vetor de características
5. CreateModel()      → combina buffer 1 + buffer 2
6. GetModel()         → lê o modelo combinado
7. UploadTemplate(0x08) → transfere 256 bytes via UART para o ESP8266
```

O template de 256 bytes é convertido para string hexadecimal de 512 caracteres antes de ser enviado via MQTT.

### Fluxo de acesso (matching)

O matching pode ser feito de duas formas:

**On-device (local):**
```
1. GenImg()    → captura imagem do dedo apresentado
2. Img2Tz(1)  → extrai vetor de características
3. Search()   → busca nos slots 1–127 da flash interna
4. Resultado: slotId encontrado (MATCH) ou NOT_FOUND
```

**Remoto (via backend):**
```
1. GenImg() + Img2Tz → extrai vetor
2. GetModel()        → obtém template
3. UploadTemplate    → envia para o ESP8266
4. ESP8266 publica access-attempt com credentialValue
5. Backend faz busca por valor na tabela access_credential
```

> ℹ️ A estratégia de matching atual usa a **busca remota** (valor do template como chave no banco). O matching local (Search on-device) é parte da implementação de offline-first (HW-008).

## Leitor RFID — RC522

O leitor RC522 é utilizado para fazer a leitura do UID de cartões e tags RFID de 13,56 MHz (padrão MIFARE).

### Especificações

| Atributo | Valor |
|---|---|
| Protocolo de comunicação | SPI |
| Frequência | 13,56 MHz |
| Tensão de alimentação | 3,3 V |
| Nível lógico | 3,3 V |

### Conexão SPI

Diferente do Wiegand, o RC522 utiliza o barramento SPI, que exige conexões específicas de clock e dados. No ESP32, utilizamos a interface VSPI (MISO, MOSI, SCK) nativa de hardware, garantindo alta velocidade de leitura.

O componente opera nativamente em 3,3V, sendo conectado diretamente aos pinos do ESP32 sem a necessidade de divisores de tensão.

## Módulo relê — 5V 1 canal

O módulo relê recebe o sinal de controle do ESP8266 (3,3V) e aciona a bobina da fechadura solenoide (12V).

### Especificações

| Atributo | Valor |
|---|---|
| Tensão de controle | 5V (com optoacoplador) |
| Tensão de carga (NO/NC) | até 250V AC / 30V DC |
| Corrente máxima | 10A |
| Nível de acionamento | LOW (ativo em nível baixo) |

> ℹ️ Módulos com optoacoplador isolam eletricamente o circuito de controle (3,3V ESP8266) do circuito de potência (12V fechadura), protegendo o microcontrolador.

### Conexão

```
ESP8266 GPIO5 (D1) → IN do módulo relê
VIN (5V) → VCC do módulo relê
GND → GND do módulo relê

Saída NA (normalmente aberta) → fio positivo da fechadura
12V da fonte → outro terminal da fechadura
```

## Fechadura solenoide — 12V (fail-secure)

A fechadura solenoide é o atuador eletromecânico que efetivamente trava e destrava a porta.

### Tipo fail-secure vs fail-safe

| Tipo | Comportamento sem energia | Uso recomendado |
|---|---|---|
| **Fail-secure** | Permanece **travada** | Salas com alto requisito de segurança |
| **Fail-safe** | Permanece **destravada** | Saídas de emergência |

O projeto utiliza **fail-secure** — em caso de queda de energia, as salas permanecem trancadas.

### Operação

- **Relé aberto (sem sinal):** bobina sem corrente → mola mantém trava fechada (fail-secure)
- **Relé fechado (GPIO HIGH):** corrente na bobina → solenoide retrai → porta pode ser aberta
- **Tempo de abertura:** 3–5 segundos após acesso GRANTED (configurável no firmware)

## Fonte de alimentação e step-down

### Dimensionamento

| Componente | Tensão | Corrente típica |
|---|---|---|
| Fechadura solenoide | 12V | 500mA – 1A (pico na abertura) |
| NodeMCU + periféricos | 5V | ~500mA |
| **Total** | — | **~1,5A @ 12V** |

Uma fonte de **12V / 2A** oferece margem confortável.

### Step-down (LM2596)

O módulo step-down converte 12V → 5V para alimentar o NodeMCU via pino VIN:

```
Fonte 12V ──┬── Relé (carga 12V da fechadura)
             │
             └── Step-down LM2596
                     │
                     └── 5V → NodeMCU VIN
```

> ⚠️ Não alimente o NodeMCU simultaneamente pelo USB e pelo VIN com tensões diferentes. Durante o desenvolvimento, use apenas USB. Em produção, use apenas o step-down via VIN.
