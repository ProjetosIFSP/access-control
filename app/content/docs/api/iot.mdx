---
title: IoT — Integração MQTT
description: Endpoints internos utilizados pelo broker MQTT para registrar controladores, processar tentativas de acesso, gerenciar comandos e acompanhar enrollments biométricos.
---

Endpoints sob o prefixo `/iot` são utilizados exclusivamente pelo **broker MQTT** (Aedes) para se comunicar com o backend. Eles não devem ser chamados diretamente pelo frontend — são a ponte entre o mundo físico dos controladores ESP8266/ESP32 e a lógica de negócio no Fastify.

> ⚠️ Estes endpoints não exigem autenticação por cookie, pois são chamados internamente pelo broker. Em produção, eles devem estar acessíveis **apenas na rede interna** (não expostos publicamente).

---

## Controladores de porta

### Registrar ou atualizar controlador

```http
PUT /iot/devices/:id
```

**Auth:** Interna (sem cookie)

Chamado quando um ESP8266/ESP32 publica no tópico `door/{id}/register`. Registra o controlador no banco caso não exista, ou atualiza seus metadados caso já esteja cadastrado.

**Parâmetros de rota:**

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `id` | string | ID único do controlador (definido no firmware) |

**Body:**

```json
{
  "roomId": "cdea3efb-650d-4c8a-a9c0-8ee97d739f5c",
  "sensorProtocol": "R30X",
  "sensorModel": "ZN-53X"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `roomId` | UUID v7 | ✅ | Sala à qual o controlador está vinculado |
| `sensorProtocol` | string | ✅ | Protocolo do sensor biométrico (ex: `"R30X"`) |
| `sensorModel` | string | ✅ | Modelo do sensor biométrico (ex: `"ZN-53X"`) |

**Resposta `200 OK`:**

```json
{
  "id": "ctrl-bloco-a-lab-101",
  "roomId": "cdea3efb-650d-4c8a-a9c0-8ee97d739f5c",
  "sensorProtocol": "R30X",
  "sensorModel": "ZN-53X",
  "lastSeenAt": "2025-07-01T12:00:00.000Z"
}
```

Após o registro, o broker inicia o **polling de comandos pendentes** para este controlador.

### Heartbeat do controlador

```http
PATCH /iot/devices/:id/heartbeat
```

**Auth:** Interna

Chamado quando o controlador publica no tópico `door/{id}/heartbeat`. Atualiza o campo `lastSeenAt` no banco para indicar que o dispositivo está online.

**Parâmetros de rota:**

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `id` | string | ID único do controlador |

**Body:** sem corpo de request.

**Resposta `200 OK`:**

```json
{
  "lastSeenAt": "2025-07-01T12:00:30.000Z"
}
```

O heartbeat é enviado pelos controladores a cada **30 segundos**. Controladores sem heartbeat recente são considerados offline na interface.

### Atualizar status da porta

```http
PUT /iot/devices/:id/status
```

**Auth:** Interna

Chamado quando o controlador publica no tópico `door/{id}/status`. Atualiza o estado da porta e da fechadura no banco de dados.

**Body:**

```json
{
  "doorState": "OPEN",
  "isLocked": false
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `doorState` | enum | ✅ | Estado físico da porta: `"OPEN"`, `"CLOSED"` ou `"UNKNOWN"` |
| `isLocked` | boolean | ❌ | Se a fechadura está travada (`true`) ou destravada (`false`) |

**Mapeamento de estado semântico:**

| `doorState` | `isLocked` | Estado exibido |
|---|---|---|
| `OPEN` | `false` / `null` | `"aberta"` |
| `CLOSED` | qualquer | `"fechada"` |
| `OPEN` | `true` | `"alerta"` — porta aberta forçadamente |
| `UNKNOWN` | qualquer | `"alerta"` |

**Resposta `200 OK`:**

```json
{
  "id": "ctrl-bloco-a-lab-101",
  "doorState": "OPEN",
  "isLocked": false,
  "lastStatusUpdateAt": "2025-07-01T12:01:00.000Z"
}
```

## Controle de acesso

### Processar tentativa de acesso

```http
POST /iot/access
```

**Auth:** Interna

Endpoint central do sistema. Chamado pelo broker quando um controlador publica no tópico `door/{id}/access-attempt`. Recebe a credencial apresentada, verifica a permissão e retorna a decisão.

**Body:**

```json
{
  "controllerId": "ctrl-bloco-a-lab-101",
  "credentialValue": "a3f9c2e1d4b8...",
  "credentialType": "FINGERPRINT"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `controllerId` | string | ✅ | ID do controlador que recebeu a credencial |
| `credentialValue` | string | ✅ | Valor da credencial (template hex para biometria, UID para NFC) |
| `credentialType` | enum | ✅ | Tipo da credencial: `"FINGERPRINT"` ou `"NFC_TAG"` |

**Fluxo interno:**

```
1. Busca o controlador → obtém roomId
2. Busca o usuário pela credencial (access_credential.value)
3. Executa verifyAccess(userId, roomId) — 4 níveis de permissão
4. Registra access_log (GRANTED ou DENIED + reason)
5. Retorna decisão ao broker
```

**Resposta `200 OK` — Acesso concedido:**

```json
{
  "decision": "GRANTED",
  "userId": "7b3cf58e-353f-48de-b2fd-6f203d64d3f8",
  "userName": "Ana Souza",
  "roomId": "cdea3efb-650d-4c8a-a9c0-8ee97d739f5c",
  "logId": "01951234-abcd-7000-8000-000000000070"
}
```

**Resposta `200 OK` — Acesso negado:**

```json
{
  "decision": "DENIED",
  "reason": "CREDENTIAL_NOT_FOUND",
  "logId": "01951234-abcd-7000-8000-000000000071"
}
```

**Valores de `reason` quando DENIED:**

| Valor | Descrição |
|---|---|
| `CREDENTIAL_NOT_FOUND` | Nenhuma credencial cadastrada com este valor |
| `PERMISSION_DENIED` | Usuário encontrado, mas sem permissão para a sala |
| `CONTROLLER_NOT_FOUND` | ID de controlador não registrado no sistema |

Após receber `GRANTED`, o broker automaticamente enfileira um comando `UNLOCK` para o controlador e publica `door/{id}/access-result` com a decisão.

> ⚠️ **Gap atual (PERM-005):** o fluxo atual verifica apenas PERM-001 (permissão direta usuário → sala). A integração completa com `verifyAccess` cobrindo os 4 níveis está pendente.

## Comandos para controladores

### Listar comandos pendentes

```http
GET /iot/devices/:id/commands/pending
```

**Auth:** Interna

Retorna os comandos pendentes para o controlador, em ordem de criação. Usado pelo broker no polling periódico.

**Parâmetros de query (opcionais):**

| Parâmetro | Tipo | Padrão | Descrição |
|---|---|---|---|
| `limit` | number | `10` | Número máximo de comandos retornados |

**Resposta `200 OK`:**

```json
[
  {
    "id": "01951234-abcd-7000-8000-000000000080",
    "command": "UNLOCK",
    "payload": null,
    "createdAt": "2025-07-01T12:01:05.000Z",
    "expiresAt": "2025-07-01T12:02:05.000Z"
  }
]
```

**Comandos disponíveis:**

| Comando | Descrição |
|---|---|
| `UNLOCK` | Abre a fechadura (aciona o relé) |
| `LOCK` | Fecha a fechadura |
| `SYNC_STATE` | Solicita que o controlador publique seu estado atual |

Comandos com `expiresAt` no passado são descartados automaticamente pelo backend antes de serem retornados.

---

### Confirmar execução de comando (ACK)

```http
POST /iot/devices/:id/commands/:commandId/ack
```

**Auth:** Interna

Chamado quando o controlador publica no tópico `door/{id}/command-result`. Marca o comando como executado no banco.

**Body:**

```json
{
  "success": true,
  "executedAt": "2025-07-01T12:01:06.000Z"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `success` | boolean | ✅ | Se o comando foi executado com sucesso |
| `executedAt` | string (ISO 8601) | ✅ | Timestamp de execução no dispositivo |

**Resposta `200 OK`:**

```json
{
  "commandId": "01951234-abcd-7000-8000-000000000080",
  "acknowledged": true
}
```

---

### Enfileirar comando manualmente

```http
POST /iot/devices/:id/commands
```

**Auth:** ✅ Administrador (chamado pelo frontend)

Permite que o administrador enfileire um comando para um controlador específico via portal web.

**Body:**

```json
{
  "command": "UNLOCK",
  "ttlSeconds": 60
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `command` | enum | ✅ | Comando a executar: `"UNLOCK"`, `"LOCK"` ou `"SYNC_STATE"` |
| `ttlSeconds` | number | ❌ | Tempo em segundos antes de o comando expirar (padrão: 60) |

**Resposta `201 Created`:**

```json
{
  "id": "01951234-abcd-7000-8000-000000000081",
  "command": "UNLOCK",
  "expiresAt": "2025-07-01T12:03:00.000Z",
  "createdAt": "2025-07-01T12:02:00.000Z"
}
```

## Enrollment biométrico

### Concluir enrollment

```http
POST /iot/enrollment/complete
```

**Auth:** Interna

Chamado pelo broker quando um controlador em modo terminal publica o tópico `door/{id}/enrollment-result` com o template biométrico capturado.

**Body:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "template": "a3f9c2e1d4b8...",
  "quality": 85,
  "status": "SUCCESS"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `enrollmentId` | UUID v7 | ✅ | ID do enrollment_request em andamento |
| `template` | string | Condicional | Template biométrico em hexadecimal (512 chars = 256 bytes). Obrigatório quando `status` é `"SUCCESS"` |
| `quality` | number | ❌ | Qualidade da captura (0–100) reportada pelo sensor |
| `status` | enum | ✅ | Resultado: `"SUCCESS"`, `"FAILED"` ou `"EXPIRED"` |

**Fluxo interno (quando `status === "SUCCESS"`):**

```
1. Valida enrollmentId → obtém userId, finger e controllerId
2. Insere access_credential no banco
   (enrolledByControllerId = controllerId da fechadura que capturou)
3. Dispara sincronização para todos os controladores
   com o mesmo sensorProtocol:
   → Publica door/{id}/sync-credentials para cada um
4. Atualiza enrollment_request.status = "SUCCESS"
5. Retorna confirmação
```

**Resposta `200 OK`:**

```json
{
  "credentialId": "01951234-abcd-7000-8000-000000000050",
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "syncedControllers": 3
}
```

**Resposta quando `status !== "SUCCESS"`:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "status": "EXPIRED",
  "credentialId": null
}
```

### Consultar status do enrollment

```http
GET /iot/enrollment/:enrollmentId/status
```

**Auth:** ✅ Administrador (chamado pelo frontend em polling)

Permite que o portal web acompanhe o progresso de um enrollment biométrico em andamento.

**Parâmetros de rota:**

| Parâmetro | Tipo | Descrição |
|---|---|---|
| `enrollmentId` | UUID v7 | ID do enrollment_request |

**Resposta `200 OK`:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "status": "PENDING",
  "finger": "RIGHT_INDEX",
  "userId": "7b3cf58e-353f-48de-b2fd-6f203d64d3f8",
  "controllerId": "ctrl-bloco-a-lab-101",
  "expiresAt": "2025-07-01T12:02:00.000Z",
  "createdAt": "2025-07-01T12:00:00.000Z"
}
```

**Valores de `status`:**

| Valor | Descrição |
|---|---|
| `PENDING` | Aguardando o usuário apresentar o dedo na fechadura |
| `SUCCESS` | Digital capturada e credencial cadastrada com sucesso |
| `FAILED` | Captura falhou (qualidade insuficiente ou erro no sensor) |
| `EXPIRED` | TTL expirou sem captura — enrollment deve ser reiniciado |

**Erros:**

| Status | Quando |
|---|---|
| `404 Not Found` | enrollmentId não encontrado |

## Sincronização de credenciais

### Confirmar sincronização

```http
POST /iot/devices/:id/sync-result
```

**Auth:** Interna

Chamado pelo broker quando um controlador publica `door/{id}/sync-result`, confirmando quais slots biométricos foram carregados no sensor ZN-53X.

**Body:**

```json
{
  "loadedSlots": [
    { "slotId": 1, "credentialId": "01951234-abcd-7000-8000-000000000050" },
    { "slotId": 2, "credentialId": "01951234-abcd-7000-8000-000000000051" }
  ],
  "evictedSlots": [3]
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `loadedSlots` | array | Slots que foram carregados com sucesso no sensor |
| `evictedSlots` | array | Slots que foram removidos (política de eviction HW-008) |

**Resposta `200 OK`:**

```json
{
  "controllerId": "ctrl-bloco-a-lab-101",
  "updatedSlots": 2,
  "syncedAt": "2025-07-01T12:01:30.000Z"
}
```

O backend atualiza a tabela `controller_credential_slot` com o `slotId`, `credentialId` e `syncedAt` para cada slot confirmado.
