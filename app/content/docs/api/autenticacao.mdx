Todos os fluxos de autenticação são gerenciados pelo **better-auth** e expostos sob o prefixo `/auth`. A autenticação é baseada em **sessão por cookie `HttpOnly`** — sem JWT no localStorage.

Para um guia completo sobre o funcionamento da autenticação, veja [Autenticação](/docs/guia/autenticacao).

---

## Login

```http
POST /auth/sign-in/email
Content-Type: application/json
```

**Auth:** ❌ Público

**Body:**

```json
{
  "email": "admin@ifsp.edu.br",
  "password": "Admin@123"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `email` | string | ✅ | E-mail do usuário cadastrado |
| `password` | string | ✅ | Senha do usuário |

**Resposta `200 OK`:**

```json
{
  "user": {
    "id": "01951234-abcd-7000-8000-000000000001",
    "name": "Administrador",
    "email": "admin@ifsp.edu.br",
    "emailVerified": true,
    "createdAt": "2025-01-01T00:00:00.000Z",
    "updatedAt": "2025-07-01T00:00:00.000Z"
  },
  "session": {
    "id": "01951234-abcd-7000-8000-000000000002",
    "userId": "01951234-abcd-7000-8000-000000000001",
    "expiresAt": "2025-08-01T00:00:00.000Z",
    "createdAt": "2025-07-01T00:00:00.000Z",
    "updatedAt": "2025-07-01T00:00:00.000Z"
  }
}
```

O cookie `auth_session` é definido automaticamente no header `Set-Cookie` da resposta. O browser o enviará em todas as requisições subsequentes.

**Erros:**

| Status | Quando |
|---|---|
| `401 Unauthorized` | Credenciais inválidas (e-mail ou senha incorretos) |
| `400 Bad Request` | Campos obrigatórios ausentes ou formato inválido |

## Logout

```http
POST /auth/sign-out
```

**Auth:** ✅ Sessão ativa

Invalida a sessão atual no banco de dados e limpa o cookie `auth_session`. Nenhum corpo de request é necessário — o cookie é enviado automaticamente pelo browser.

**Resposta `200 OK`:**

```json
{
  "success": true
}
```

Após o logout, qualquer requisição a endpoints protegidos retornará `401 Unauthorized`.

## Sessão atual

```http
GET /auth/get-session
```

**Auth:** Opcional

Retorna os dados do usuário e da sessão atualmente autenticados. Útil para o frontend verificar se o usuário está logado e obter as informações do perfil.

**Resposta `200 OK` (autenticado):**

```json
{
  "user": {
    "id": "01951234-abcd-7000-8000-000000000001",
    "name": "Administrador",
    "email": "admin@ifsp.edu.br",
    "emailVerified": true,
    "createdAt": "2025-01-01T00:00:00.000Z",
    "updatedAt": "2025-07-01T00:00:00.000Z"
  },
  "session": {
    "id": "01951234-abcd-7000-8000-000000000002",
    "userId": "01951234-abcd-7000-8000-000000000001",
    "expiresAt": "2025-08-01T00:00:00.000Z",
    "createdAt": "2025-07-01T00:00:00.000Z",
    "updatedAt": "2025-07-01T00:00:00.000Z"
  }
}
```

**Resposta `200 OK` (sem sessão):**

```json
null
```

## Solicitar redefinição de senha

```http
POST /auth/forget-password
Content-Type: application/json
```

**Auth:** ❌ Público

Envia um e-mail com link de redefinição de senha para o endereço informado. O token gerado é de uso único e tem TTL curto (configurável no better-auth).

**Body:**

```json
{
  "email": "admin@ifsp.edu.br",
  "redirectTo": "http://localhost:3000/reset-password"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `email` | string | ✅ | E-mail do usuário que quer redefinir a senha |
| `redirectTo` | string | ✅ | URL para onde o link no e-mail irá redirecionar (com `?token=...` anexado automaticamente) |

**Resposta `200 OK`:**

```json
{
  "status": true
}
```

> ℹ️ Por segurança, o endpoint retorna `200` mesmo que o e-mail não esteja cadastrado, para não revelar quais endereços existem no sistema.

**Erros:**

| Status | Quando |
|---|---|
| `400 Bad Request` | Campos obrigatórios ausentes ou e-mail com formato inválido |
| `500 Internal Server Error` | Falha no envio do e-mail (configuração SMTP incorreta) |

## Redefinir senha

```http
POST /auth/reset-password
Content-Type: application/json
```

**Auth:** ❌ Público (requer token válido)

Redefine a senha do usuário usando o token recebido por e-mail. Após o uso, o token é invalidado automaticamente.

**Body:**

```json
{
  "token": "token-recebido-por-email",
  "newPassword": "NovaSenha@456"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `token` | string | ✅ | Token extraído da URL do e-mail de redefinição |
| `newPassword` | string | ✅ | Nova senha do usuário |

**Resposta `200 OK`:**

```json
{
  "status": true
}
```

**Erros:**

| Status | Quando |
|---|---|
| `400 Bad Request` | Token inválido, expirado ou já utilizado |
| `400 Bad Request` | Nova senha não atende aos requisitos mínimos |

## Comportamento do cookie de sessão

| Atributo | Valor | Motivo |
|---|---|---|
| `HttpOnly` | `true` | Inacessível via JavaScript — protege contra XSS |
| `Secure` | `true` (produção) | Enviado apenas em conexões HTTPS |
| `SameSite` | `Lax` | Protege contra CSRF em requests cross-site |
| `Path` | `/` | Válido para todas as rotas da aplicação |
| Expiração | 7 dias | Configurável em `auth.ts` via `session.expiresIn` |

A sessão é renovada automaticamente a cada 24 horas de uso ativo (`session.updateAge`). Sessões inativas por mais de 7 dias expiram automaticamente.
