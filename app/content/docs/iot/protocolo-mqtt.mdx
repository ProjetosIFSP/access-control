---
title: Protocolo MQTT
description: Tópicos, payloads e fluxos de comunicação MQTT entre o broker Aedes e os controladores físicos ESP8266/ESP32.
---

O broker MQTT é o coração da comunicação entre o backend e os controladores físicos instalados nas portas. Ele é implementado com **Aedes** (Node.js) e aceita conexões via **TCP** (porta 1883) e **WebSocket** (porta 9001).

---

## Conexão

Os controladores ESP8266/ESP32 se conectam ao broker usando a biblioteca **PubSubClient** (Arduino). O `clientId` deve ser o mesmo ID do controlador registrado no sistema.

```cpp
// Exemplo de configuração no firmware
const char* MQTT_SERVER = "192.168.1.100";
const int   MQTT_PORT   = 1883;
const char* CLIENT_ID   = "ctrl-bloco-a-lab-101";

mqttClient.setServer(MQTT_SERVER, MQTT_PORT);
mqttClient.setCallback(onMessageReceived);
mqttClient.connect(CLIENT_ID);
```

---

## Convenção de tópicos

Todos os tópicos seguem o padrão:

```
door/{controllerId}/{ação}
```

Onde `controllerId` é o identificador único do controlador físico (definido no firmware e persistido em EEPROM).

| Prefixo | Direção | Descrição |
|---|---|---|
| `door/{id}/register` | Device → Broker | Registro e anúncio inicial |
| `door/{id}/heartbeat` | Device → Broker | Keep-alive periódico |
| `door/{id}/status` | Device → Broker | Estado da porta e fechadura |
| `door/{id}/access-attempt` | Device → Broker | Credencial apresentada |
| `door/{id}/access-result` | Broker → Device | Decisão de acesso |
| `door/{id}/command` | Broker → Device | Comando administrativo |
| `door/{id}/command-result` | Device → Broker | ACK do comando executado |
| `door/{id}/enter-enrollment-mode` | Broker → Device | Inicia captura biométrica |
| `door/{id}/cancel-enrollment` | Broker → Device | Cancela enrollment em andamento |
| `door/{id}/enrollment-result` | Device → Broker | Template capturado + status |
| `door/{id}/sync-credentials` | Broker → Device | Envia lista de templates para carregar |
| `door/{id}/sync-result` | Device → Broker | Confirma slots carregados |
| `door/{id}/delete-credential` | Broker → Device | Remove template de um slot |

## Tópicos detalhados

### `door/{id}/register` — Device → Broker

Publicado pelo controlador logo após conectar ao broker. Informa o hardware disponível e a sala à qual está vinculado.

**Payload:**

```json
{
  "roomId": "cdea3efb-650d-4c8a-a9c0-8ee97d739f5c",
  "sensorProtocol": "R30X",
  "sensorModel": "ZN-53X",
  "firmwareVersion": "1.2.0"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `roomId` | UUID v7 | ✅ | Sala à qual este controlador está instalado |
| `sensorProtocol` | string | ✅ | Protocolo do sensor biométrico (ex: `"R30X"`) |
| `sensorModel` | string | ✅ | Modelo exato do sensor (ex: `"ZN-53X"`) |
| `firmwareVersion` | string | ❌ | Versão do firmware para diagnóstico |

**Ação do broker:** chama `PUT /iot/devices/:id` no backend e inicia o polling de comandos pendentes.

---

### `door/{id}/heartbeat` — Device → Broker

Publicado a cada **30 segundos** para sinalizar que o controlador está online.

**Payload:**

```json
{
  "uptime": 3600,
  "rssi": -65
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `uptime` | number | ❌ | Tempo de operação em segundos desde o boot |
| `rssi` | number | ❌ | Intensidade do sinal Wi-Fi em dBm |

**Ação do broker:** chama `PATCH /iot/devices/:id/heartbeat` no backend para atualizar `lastSeenAt`.

---

### `door/{id}/status` — Device → Broker

Publicado a cada **500ms** com o estado atual da porta (lido do reed switch) e da fechadura (lido do relé).

**Payload:**

```json
{
  "doorState": "OPEN",
  "isLocked": false
}
```

| Campo | Tipo | Valores | Descrição |
|---|---|---|---|
| `doorState` | enum | `"OPEN"`, `"CLOSED"`, `"UNKNOWN"` | Estado físico da porta |
| `isLocked` | boolean | `true`, `false` | Estado da fechadura eletrônica |

**Mapeamento para estado semântico (exibido no frontend):**

| `doorState` | `isLocked` | Estado |
|---|---|---|
| `OPEN` | `false` | `"aberta"` — uso normal |
| `CLOSED` | qualquer | `"fechada"` — porta fechada |
| `OPEN` | `true` | `"alerta"` — porta aberta forçadamente |
| `UNKNOWN` | qualquer | `"alerta"` — sensor sem leitura |

**Ação do broker:** chama `PUT /iot/devices/:id/status` no backend.

---

### `door/{id}/access-attempt` — Device → Broker

Publicado quando um usuário apresenta uma credencial (digital ou tag NFC) ao sensor.

**Payload — biometria:**

```json
{
  "credentialType": "FINGERPRINT",
  "credentialValue": "a3f9c2e1d4b8e72f...",
  "timestamp": "2025-07-01T12:00:00.000Z"
}
```

**Payload — NFC:**

```json
{
  "credentialType": "NFC_TAG",
  "credentialValue": "04:AB:CD:EF:12",
  "timestamp": "2025-07-01T12:00:00.000Z"
}
```

| Campo | Tipo | Obrigatório | Descrição |
|---|---|---|---|
| `credentialType` | enum | ✅ | `"FINGERPRINT"` ou `"NFC_TAG"` |
| `credentialValue` | string | ✅ | Template hex (biometria) ou UID (NFC) |
| `timestamp` | string ISO 8601 | ❌ | Timestamp local do dispositivo |

**Ação do broker:** chama `POST /iot/access` no backend e aguarda a decisão para publicar `door/{id}/access-result`.

---

### `door/{id}/access-result` — Broker → Device

Publicado pelo broker após receber a decisão do backend. O controlador deve processar esta mensagem em até **3 segundos** — após esse timeout, aplica a política offline (HW-008).

**Payload — acesso concedido:**

```json
{
  "decision": "GRANTED",
  "userId": "7b3cf58e-353f-48de-b2fd-6f203d64d3f8",
  "userName": "Ana Souza"
}
```

**Payload — acesso negado:**

```json
{
  "decision": "DENIED",
  "reason": "PERMISSION_DENIED"
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `decision` | enum | `"GRANTED"` ou `"DENIED"` |
| `userId` | UUID v7 | ID do usuário identificado (apenas em GRANTED) |
| `userName` | string | Nome do usuário (apenas em GRANTED) |
| `reason` | string | Motivo da negação (apenas em DENIED) |

**Comportamento esperado no firmware:**

- **GRANTED:** acionar relé (UNLOCK) por 3–5 segundos, LED verde, buzzer curto
- **DENIED:** manter relé fechado, LED vermelho, buzzer longo

---

### `door/{id}/command` — Broker → Device

Publicado pelo broker para enviar comandos administrativos ao controlador.

**Payload:**

```json
{
  "commandId": "01951234-abcd-7000-8000-000000000080",
  "command": "UNLOCK",
  "payload": null,
  "expiresAt": "2025-07-01T12:02:00.000Z"
}
```

| `command` | Descrição |
|---|---|
| `UNLOCK` | Aciona o relé — abre a fechadura |
| `LOCK` | Desaciona o relé — fecha a fechadura |
| `SYNC_STATE` | Publica o estado atual da porta imediatamente |

O controlador deve verificar `expiresAt` — se o timestamp já passou, o comando deve ser descartado sem execução.

---

### `door/{id}/command-result` — Device → Broker

Publicado após o controlador executar (ou rejeitar) um comando.

**Payload:**

```json
{
  "commandId": "01951234-abcd-7000-8000-000000000080",
  "success": true,
  "executedAt": "2025-07-01T12:01:06.000Z"
}
```

**Ação do broker:** chama `POST /iot/devices/:id/commands/:commandId/ack` no backend.

---

### `door/{id}/enter-enrollment-mode` — Broker → Device

Publicado pelo backend (via broker) para colocar a fechadura em **modo terminal** temporariamente, habilitando a captura biométrica.

**Payload:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "userId": "7b3cf58e-353f-48de-b2fd-6f203d64d3f8",
  "finger": "RIGHT_INDEX",
  "expiresAt": "2025-07-01T12:02:00.000Z"
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `enrollmentId` | UUID v7 | ID do enrollment_request — deve ser incluído no resultado |
| `userId` | UUID v7 | ID do usuário cuja digital será cadastrada |
| `finger` | enum | Dedo a ser capturado (ex: `"RIGHT_INDEX"`) |
| `expiresAt` | string ISO 8601 | Quando o modo terminal expira automaticamente |

O controlador deve:
1. Entrar em modo terminal (parar de processar acessos normais)
2. Acender LED azul pulsante para indicar que está aguardando o dedo
3. Capturar 2 passagens do dedo com o ZN-53X (`createModel()` → `getModel()`)
4. Publicar `door/{id}/enrollment-result` com o template ou status de falha

---

### `door/{id}/cancel-enrollment` — Broker → Device

Publicado para cancelar um enrollment em andamento e retornar ao modo fechadura imediatamente.

**Payload:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060"
}
```

O controlador deve publicar `door/{id}/enrollment-result` com `status: "FAILED"` antes de retornar ao modo normal.

---

### `door/{id}/enrollment-result` — Device → Broker

Publicado após concluir (ou falhar em) uma captura biométrica. O controlador retorna ao modo fechadura imediatamente após publicar esta mensagem.

**Payload — sucesso:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "template": "a3f9c2e1d4b8e72f...",
  "quality": 85,
  "status": "SUCCESS"
}
```

**Payload — falha ou expiração:**

```json
{
  "enrollmentId": "01951234-abcd-7000-8000-000000000060",
  "template": null,
  "quality": 0,
  "status": "EXPIRED"
}
```

| Campo | Tipo | Descrição |
|---|---|---|
| `enrollmentId` | UUID v7 | ID do enrollment_request original |
| `template` | string \| null | Template biométrico em hex (512 chars = 256 bytes). `null` em falha/expiração |
| `quality` | number | Qualidade reportada pelo sensor ZN-53X (0–100) |
| `status` | enum | `"SUCCESS"`, `"FAILED"` ou `"EXPIRED"` |

**Ação do broker:** chama `POST /iot/enrollment/complete` no backend.

---

### `door/{id}/sync-credentials` — Broker → Device

Publicado após um novo enrollment para sincronizar os templates biométricos no sensor ZN-53X do controlador.

**Payload:**

```json
{
  "credentials": [
    {
      "slotId": 1,
      "credentialId": "01951234-abcd-7000-8000-000000000050",
      "template": "a3f9c2e1d4b8..."
    },
    {
      "slotId": 2,
      "credentialId": "01951234-abcd-7000-8000-000000000051",
      "template": "b4f0d3e2c5a9..."
    }
  ]
}
```

O controlador deve chamar `storeModel(slotId, template)` para cada item e confirmar com `door/{id}/sync-result`.

---

### `door/{id}/sync-result` — Device → Broker

Confirma quais slots foram carregados com sucesso no sensor ZN-53X.

**Payload:**

```json
{
  "loadedSlots": [
    { "slotId": 1, "credentialId": "01951234-abcd-7000-8000-000000000050" },
    { "slotId": 2, "credentialId": "01951234-abcd-7000-8000-000000000051" }
  ],
  "evictedSlots": [3]
}
```

**Ação do broker:** chama `POST /iot/devices/:id/sync-result` no backend para atualizar `controller_credential_slot`.

---

### `door/{id}/delete-credential` — Broker → Device

Remove um template biométrico de um slot específico do ZN-53X, normalmente após a exclusão de uma credencial no sistema.

**Payload:**

```json
{
  "slotId": 3,
  "credentialId": "01951234-abcd-7000-8000-000000000052"
}
```

O controlador deve chamar `deleteModel(slotId)` no ZN-53X e confirmar com `door/{id}/sync-result`.
